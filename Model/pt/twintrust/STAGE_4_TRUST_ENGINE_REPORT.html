1. Executive Summary

The Trust Engine combines physical telemetry features (Stage 1), multivariate Isolation Forest novelty (Stage 2), deterministic rules (Stage 3), and operational actuator context to output a bounded Trust Score (0–100), a discrete Machine State, and an actionable Control Decision.

Architectural Principle Confirmed: The Trust Engine is 100% deterministic and explainable. No LLM or external cloud API is used to calculate trust scores or make machine control decisions.

3. Key Behavioral Solutions Delivered

  • Fan OFF Context Suppression: Stage 2 flags 100% of fan-off readings as anomalous because it was trained on running data. Stage 4 recognizes fan_int == 0.0 and suppresses the anomaly penalty, keeping score at 100.0 (ALLOW).
  • Mechanical Fan STALL: Upon 3 consecutive readings with fan ON and RPM $\le 150$, Stage 3 triggers FAN_STALL (CRITICAL), instantly forcing FAULT state and BLOCK decision.
  • Double-Counting Mitigation: When critical rules fire alongside an Isolation Forest anomaly, the statistical anomaly penalty is scaled by $0.5$ because the event is already physically explained.
  • Temporal Degradation Recognition: Adverse trends in temperature rate ($> +0.05$ °C/s), RPM drop ($< -10$ RPM/s), and current increase ($> +0.005$ A/s) apply bounded degradation penalties and transition the machine into DEGRADING.

5. Downstream LLM Explanation Contract

The structured TrustResult contains deterministic ground truth. The downstream LLM receives structured reasons and key sensor values to generate human-readable explanations. It is strictly prohibited from altering trust scores, states, or control recommendations.
